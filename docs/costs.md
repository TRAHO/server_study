# 비용이 드는 항목 — 왜 필요한가

로드맵을 따를 때 돈이 나가는 항목과, 각각이 **없으면 안 되는 이유**를 정리한다.

---

## 1. 마스터 도메인 (연 단위)

**역할:** 에이전시 브랜드 주소. 제어판 URL·네임서버(`ns1.` / `ns2.`)의 기준이 된다.

**왜 필요한가**
- IP만으로 운영하면 제어판·네임서버 안내가 지저분하고 신뢰도가 떨어진다.
- 고객에게 “네임서버를 여기로 바꿔 주세요”라고 안내하려면 **우리 도메인 밑의 NS 이름**이 필요하다.
- SSL도 도메인 단위로 발급된다.

**없으면:** 서버는 떠도 “우리 호스팅”으로 보이는 주소 체계가 없다.

---

## 2. 가상 서버 (월 단위) ← 비용의 핵심

**역할:** 실제로 홈페이지·DB·제어판이 돌아가는 컴퓨터.

**왜 필요한가**
- 고객 사이트 파일, PHP, Apache, MariaDB, 제어판이 **이 위에서** 실행된다.
- 카페24·가비아 같은 호스팅을 “사서 쓰는” 대신, **우리가 사서 나눠 주는** 구조의 본체다.

**없으면:** 입주·호스팅 사업 자체가 성립하지 않는다.

---

## 3. 블록 스토리지 (월, 용량만큼)

**역할:** OS 디스크와 분리된, 웹 데이터·DB용 추가 디스크.

**왜 필요한가**
- OS 디스크만 쓰면 용량이 빨리 차고, **서버를 끄고** 늘려야 하는 경우가 있다.
- 데이터 디스크를 분리하면 **서비스 유지한 채 용량만 확장**하기 쉽다.
- 백업·이전 시에도 “사이트 데이터만” 다루기 수월하다.

**없으면:** 당장 운영은 되지만, 고객이 늘면 디스크 때문에 먼저 막힌다.  
**초기 절약:** 아주 초기에 OS 디스크만으로 테스트할 수는 있으나, 실서비스 전에는 분리 권장.

---

## 4. 트래픽·공인 IP (상품 포함 / 초과 시)

**역할:** 인터넷에서 서버로 들어오는 길(공인 IP), 방문자가 페이지를 받을 때 쓰는 데이터양(트래픽).

**왜 필요한가**
- 공인 IP가 없으면 외부(고객·방문자)가 사이트에 접속할 수 없다.
- 트래픽은 “사이트가 열리는 만큼” 나가므로, 포함량을 넘기면 추가 과금이 생긴다.

**없으면:** 웹 서비스 불가. (보통 서버 상품에 기본 포함)

---

## 5. 제어판 — Plesk(유료) vs aaPanel(무료)

**역할:** 사이트 추가, FTP, DB, SSL, 백업을 마우스으로 관리하는 화면.

**왜 필요한가**
- SSH만으로 고객 100개를 수동 관리하면 실수·인건비가 폭증한다.
- “고객사 방 하나 만들기(Add Site)”가 사업 운영의 기본 단위다.

| 선택 | 비용 | 왜 고르나 |
|------|------|-----------|
| aaPanel | 무료 | 비용 절감, 학습·소규모에 적합 |
| Plesk | 유료 | 다중 고객·권한·안정성·지원이 더 사업용에 가깝다 |

**없으면:** 서버는 있어도 “호스팅 업체처럼” 돌리기 어렵다.

---

## 6. 외부 백업 저장소 (Drive 여유 / S3 사용량)

**역할:** 서버가 죽거나 실수로 지워도 복구할 **서버 밖** 복사본.

**왜 필요한가**
- 서버 디스크만 백업하면 **서버·디스크가 같이 날아가는** 장애에 무력하다.
- 고객 사이트·DB는 돈·신뢰 문제라, “매일 외부로 빼 두기”가 최소 안전장치다.

**없으면:** 장애 한 번에 고객 데이터를 잃을 수 있다.  
**비용:** Google Drive 무료 용량으로 시작할 수 있고, 커지면 S3 등으로 확장.

---

## 7. (선택) ELCAP 방화벽

**역할:** 서버로 들어오는 포트(22, 80, 443 등)를 클라우드 단에서 제한.

**왜 필요한가**
- SSH(22)를 전 세계에 열어 두면 해킹 시도가 끊이지 않는다.
- 웹에 필요한 문만 열어 두면 공격 면적이 줄어든다.

**없으면:** OS 방화벽만으로도 가능하지만, 클라우드 방화벽이 한 겹 더 안전하다.  
비용은 상품 정책에 따라 무료~소액.

## 한 줄 요약

| 돈 나가는 것 | 한 줄로 |
|--------------|---------|
| 도메인 | 우리 호스팅의 **이름·네임서버 간판** |
| 가상 서버 | 사이트가 돌아가는 **건물** |
| 블록 스토리지 | 고객 데이터를 쌓는 **창고 (늘리기 쉬운)** |
| 제어판 | 고객 방을 만들고 관리하는 **관리실** |
| 외부 백업 | 불이 나도 살리는 **금고 복사본** |
| 방화벽 | 필요한 문만 여는 **경비** |
