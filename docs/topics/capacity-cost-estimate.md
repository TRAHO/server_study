## 1. 현재 호스팅 통계 요약

카페24 리셀러 계정 통계(호스팅통계) 기준. 디스크·트래픽 수치는 시트 단위를 MB로 보고 GiB/GB로 환산.

| 항목 | 값 | 쉽게 말하면 |
|------|-----|-------------|
| 계정 수 | **129** | 고객 사이트(방)가 129개 |
| 디스크 실사용 | 약 **129 GiB** | 실제로 파일이 차지한 양 |
| 디스크 할당 합 | 약 **1.14 TiB** | 상품상 “쓸 수 있게 열어 둔” 양 (실사용의 약 9배) |
| 사용률 | 약 **11%** | 할당보다 실제 사용이 훨씬 적음 |
| 일별 평균 트래픽 합 | 약 **177 GB/일** | 전 계정 합산. 월로 보면 대략 **5TB 전후** |
| 특이 계정 | `yangjae` 등 | **단독** 표기 — 일반 묶음과 성격이 다름 |

트래픽이 큰 계정 예: `myk2025`, `graypipple` 등 소수가 전체를 크게 차지한다.

## 2. 용어 (비전문가용)

| 말 | 뜻 |
|----|-----|
| **가상 서버(VM)** | 클라우드에서 빌려 쓰는 컴퓨터 1대. 소유가 아니라 **월 이용**에 가깝다. |
| **공유형(vgna)** | 그 컴퓨터의 CPU를 다른 손님 VM과 **나눠 씀**. 더 저렴, 성능이 가끔 들쭉날쭉할 수 있음. |
| **단독형(gna)** | 할당된 CPU를 **우리 VM이 거의 독점**. 더 비싸지만 성능이 비교적 일정. |
| **고객을 몇 명 넣느냐** | 공유형/단독형과 무관. VM 안에서 제어판으로 방을 몇 개 만들지는 **우리가 정함**. |
| **블록 스토리지** (= 데이터 디스크) | 서버에 붙이는 **추가 하드**. 고객 사이트·DB를 여기 둠. 나중에 용량만 늘 수 있음. |
| **트래픽** | 방문자가 사이트를 볼 때 나가는 데이터 양. 기본 제공량을 넘으면 **추가 요금**. |
| **제어판** | 고객 방 만들기·SSL·DB를 마우스으로 하는 관리 화면 (aaPanel 무료 / Plesk 유료). |

**디스크 역할:** 기본 디스크에는 OS·제어판만, 추가 하드(데이터 디스크)에 고객 방을 둔다.  
기본 디스크에 빈 공간이 남는 것은 흔하며, 서버 요금에 묶인 용량이라 큰 낭비가 아니다. 고객 데이터를 기본 디스크에 몰아넣지 않는 편이 낫다.

카페24 일반 리셀러 상품 ≈ 성격상 **공유형**에 가깝고, 「단독」 상품만 예외에 가깝다.

## 5. 비용에서 가장 큰 변수

1. **트래픽** — 서버비와 비슷하거나 더 클 수 있음. 헤비 계정은 당분간 카페24에 두면 월 부담을 크게 줄일 수 있다.  
2. **디스크 종류** — SATA vs SSD.  
3. **서버 대수** — 한 대에 몰아넣으면 싸 보이지만 장애·부하 위험이 커진다.

---

## 6. 왜 한 대가 아닌가

- 계정 129개, 트래픽 편차가 큼.  
- 공유형 최대도 RAM 8GB라 제어판+다계정에 빠듯.  
- 한 대 장애 = 그 안 고객 전부.  
→ **메인 2대 + 헤비 분리**가 비용과 리스크의 절충이다.
