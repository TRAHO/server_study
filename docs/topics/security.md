## 무엇이 다른가

| 위협 | 카페24 | iwinv 자체 |
|------|--------|------------|
| CMS·플러그인·계정 해킹 | 발생 가능 (해당 사이트) | 발생 가능 |
| 서버 루트 SSH | 리셀러·고객은 보통 없음 | **우리가 관리하는 공격면** |
| 제어판 | 플랫폼 패널 | Plesk/aaPanel 등 **내부 관리** |
| 방 → 다른 방 확산 | 플랫폼 격리에 의존 | 기본 패널만으로는 더 취약할 수 있음. 루트·패널 탈취 시 VM 전체 위험 |

## 완화 방법 (자체 서버)

완전 차단이 아니라 **공격면 축소 + 확산 억제 + 복구**가 목표다.

| 영역 | 방법 |
|------|------|
| **SSH** | 비밀번호 로그인 금지, SSH 키만 / 22번을 사무실 IP 또는 VPN만 허용 / `fail2ban` / root 직접 로그인 금지 |
| **제어판** | 패널 포트 IP 제한 또는 VPN / 강한 관리자 암호·가능하면 2FA / 패널·OS 업데이트 |
| **방 사이 확산** | 사이트별 시스템 유저·PHP-FPM 풀 / `777` 금지 / 여유 시 CloudLinux·CageFS급 격리 또는 중요 고객 서버 분리 |
| **CMS·계정** | 코어·플러그인 업데이트 / 관리자 암호 강화 / 불필요 플러그인 제거 / 멀웨어·파일 변경 감시 *(카페24 사이트에도 동일)* |
| **침해 후** | 외부 백업 + 복구 연습 / 로그인·트래픽 이상 모니터링 → [backup-recovery.md](./backup-recovery.md) |

**한 줄:** 밖은 SSH·패널 문을 좁히고, 안은 유저·권한으로 방을 가르며, CMS는 업데이트·암호, 최후는 외부 백업.
