# 장애 대응

브리핑 → [report-hosting-comparison.md](../report-hosting-comparison.md)

## 무엇이 다른가

| | 카페24 리셀러 | iwinv 자체 |
|--|---------------|------------|
| 서버·디스크·네트워크 장애 | 플랫폼이 1차 복구 | **내부가** 진단·복구 |
| 그 노드/VM의 고객 | **다수 동시 영향** | **다수 동시 영향** (동일 유형) |
| 에이전시 역할 | 상태 확인·고객 안내 중심 | 복구 실행 + 고객 안내 |

다수 고객이 동시에 영향받는 것 자체가 자체만의 문제는 아니다.  
차이는 **복구 주체**다.

## 자체 운영 시 대응 방향

1. 모니터링: 서버·디스크·HTTP 상태 알림
2. 연락 체계: 장애 시 누가·몇 분 안에 붙는지 정해 두기
3. 복구 런북: 재시작 → 디스크/네트워크 확인 → 패널·웹·DB 순서
4. 외부 백업으로 “살리지 못할 때” 복구 경로 확보 → [backup-recovery.md](./backup-recovery.md)
5. 영향 범위 축소: 고객을 서버에 나눠 담기 → [scaling-ops.md](./scaling-ops.md)
