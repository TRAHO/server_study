# 호스팅 운영 방식 브리핑

**대상:** 카페24 리셀러(현행) / 스마일서브 iwinv 자체 호스팅(검토 중인 운영 방식)  
**배경:** 고객 규모가 이미 커진 상태에서, 현행 리셀러 외 운영 방식을 살펴보는 브리핑  
**성격:** 두 방식의 구조·특성·차이를 설명하는 자료  
**상세 운영·대응 방법:** 하단 [주제별 문서](#주제별-문서) 참고

---

## 1. 한눈에 보기

두 방식 모두 고객에게 도메인·계정·용량 단위의 “호스팅 방”을 제공한다.  
갈리는 지점은 **서버를 누가 소유하고, 장애·보안·백업을 누가 책임지느냐**이다.

| | 카페24 리셀러 | iwinv 자체 호스팅 |
|--|---------------|-------------------|
| 서버 | 카페24 | 에이전시(가상 서버) |
| 인프라 복구 | 플랫폼 | 내부 |
| 방 나누기 | 카페24 플랫폼 | 제어판(Plesk/aaPanel 등) |
| 비용 구조 | 고객·상품 수에 **비례해 납부액이 증가** | 서버·스토리지 등 **인프라 단위**로 과금 (규모에 따라 대수·스펙 확장) |
| 구성 자유도 | 상품 범위 안 | 높음(OS·스택 직접) |
| 운영 부담 | 인프라 운영은 상대적 낮음 | 인프라까지 상대적 높음 |

---

## 2. 각 방식이 어떻게 돌아가는지

### 카페24 리셀러

에이전시가 계정·도메인·고객 응대·과금을 맡고, 서버·네트워크·스토리지 운영은 카페24 플랫폼이 담당한다.

```
에이전시 ──(계정 생성)──▶ 카페24 서버 팜(여러 노드)
                              ├─ 노드A (고객들)
                              ├─ 노드B (고객들)
                              └─ ...
```

### iwinv 자체 호스팅

에이전시가 가상 서버를 구매하고, 제어판으로 고객 방을 만들며, OS·웹스택·백업·보안까지 직접 운영한다.

```
에이전시 ──(제어판)──▶ iwinv 가상서버
                         ├─ 고객A
                         ├─ 고객B
                         └─ ...
```

서버를 여러 대 두면 분산 **형태**는 카페24와 비슷해 보일 수 있다.  
다만 계정 자동 배정·통합 관리 플랫폼까지는 별도로 갖춰야 하며, 서버만 늘린다고 동일해지지는 않는다.

---

## 3. 고객 “방”은 어떻게 나뉘는가

기술적으로 둘 다 **공유 호스팅**에 가깝다. (방 = 기본으로 별도 VM이 아님)

| | 가능 | 기본으로는 아님 |
|--|------|----------------|
| 도메인·디스크·DB·SSL·트래픽 상한 | 방마다 분리·할당 | |
| 서버·공인 IP·전체 회선 | | 여러 방이 공유 |
| 노드(서버) 장애 시 | | 그 노드(VM)에 있는 고객이 **같이** 영향 |

카페24와 자체의 차이는 “동시 영향이 있느냐”보다 **복구·격리·루트 권한을 누가 갖느냐**에 있다.

## 4. 장단점 요약

### 카페24 리셀러

| 장점 | 단점 |
|------|------|
| 인프라 운영 부담이 적음 | 상품·모듈·스펙 제약 |
| 인프라 장애 복구는 플랫폼이 수행 | 원가·정책이 플랫폼에 종속 |
| 상품 단위 확장이 단순 | 고객이 늘수록 **납부 원가가 선형에 가깝게 증가** |
| 현행 유지 시 전환 리스크 없음 | 인프라 가시성·통제권 제한 / 특수·커스텀에 불리할 수 있음 |

### iwinv 자체 호스팅

| 장점 | 단점 |
|------|------|
| 스택·보안·용량 정책을 직접 설계 | 장애·보안·백업의 최종 책임이 내부 |
| 규모가 클 때 인프라 단위로 원가 구조 재편 여지 | 서버·스토리지 등 인프라 비용을 직접 짐 |
| 네임서버·제어판 등 브랜드 자체화 용이 | 리눅스·패널 운영 인력·지식 필요 |
| 레거시·특수 환경 맞춤에 유리 | 단일 VM 집중 시 영향 범위·운영 복잡도 증가 |

## 5. 비용 구조 (개념)

이미 고객이 많은 전제에서는 “고정비가 싸다/비싸다”보다 **원가가 무엇에 비례하느냐**가 중요하다.

| | 카페24 리셀러 | iwinv 자체 |
|--|---------------|------------|
| 과금 단위 | 계정·상품(고객 수·요금제에 비례) | 서버·스토리지·트래픽·(선택) 유료 패널 |
| 규모가 클 때 | 납부액이 고객 증가에 따라 계속 쌓임 | 서버 채워 가며 단가 구조를 바꿀 여지 (대신 운영 책임↑) |
| 숨은 비용 | 상대적으로 인프라 인력 부담은 적음 | 장애 대응·관리 인건비·학습 |

## 6. 자체 호스팅에서 달라지는 운영 성격

자체로 가면 “호스팅 공장”을 직접 돌리게 된다. 아래는 운영 방식이 바뀌며 생기는 특성이다.

| 영역 | 무엇이 달라지는가 |
|------|-------------------|
| 장애 | 인프라 복구 주체가 내부. 다수 동시 영향은 카페24 노드 장애와 같은 유형 |
| 보안 | 루트 SSH·자체 패널·OS까지 내부 관리. CMS 해킹 자체는 양쪽 모두 가능 |
| 백업 | 서버 밖 백업·복구 절차를 직접 운영 |
| 이전 | OS·PHP 버전 차이로 사이트별 검증 부담 |
| 규모 | 서버 추가·고객 배정·이중 창구(리셀러 병행 시)를 내부에서 설계 |

## 7. 우리 규모로 보면

호스팅 통계 기준으로 **지금 대략 이 정도**이다.

| 항목 | 숫자 | 무슨 뜻인가 |
|------|------|-------------|
| 고객 방(계정) | **약 129개** | 관리 중인 호스팅 계정이 이 정도 |
| 실제 저장 용량 | **약 130GB** | 사이트 파일이 실제로 차지한 합 |
| 상품상 열어 둔 용량 | **약 1.1TB** | “할당”은 크지만, 실제로는 그 일부를 쓰는 중 |
| 하루 트래픽 합 | **약 177GB** | 전 사이트 합. 월로 환산하면 **대략 5TB 전후** |
| 특징 | 트래픽 편차 큼 | 소수 사이트가 트래픽을 많이 쓰고, 「단독」 계정도 있음 |

이 규모는 “서버 한 대·작은 사양”으로 끝나기 어렵다.  
**여러 대로 나누고**, 트래픽 큰 곳은 **따로** 두는 쪽이 안전하다.

## 8. iwinv에서 쓰는 말 (짧게)

클라우드 서버는 PC를 **사서 소유**한다기보다, 스마일서브 장비를 **월 요금으로 빌려 쓰는** 형태에 가깝다.

| 말 | 쉽게 |
|----|------|
| **가상 서버** | 빌린 컴퓨터 1대 |
| **공유형** | CPU를 다른 손님과 나눔 → 대체로 저렴, 성능이 가끔 흔들릴 수 있음 |
| **단독형** | 할당 CPU를 우리가 거의 독접 → 더 비싸지만 비교적 안정 |
| **고객 몇 명** | 공유형/단독형과 별개. 한 서버에 방을 몇 개 만들지는 우리가 정함 |
| **블록 스토리지** | 사이트 데이터를 두는 추가 저장공간 (나중에 용량 확장에 유리) |
| **트래픽 요금** | 기본으로 주는 데이터양을 넘기면 추가 과금 |

카페24 **일반** 리셀러 ≈ 성격상 **공유형**에 가깝고, 「단독」 상품만 예외에 가깝다.

## 9. 규모에 맞는 상품·비용 감 (부가세 별도)

요금은 [iwinv 공개 요금](https://www.iwinv.kr/server/server) 기준 예시이며, 시점·실트래픽에 따라 달라질 수 있다.

### 추천 방향 (한 줄)

**단독형 메인 서버 2대 + 트래픽 큰 고객용 1대 + 데이터용 추가 디스크.**  
공유형 최대(8GB 메모리)는 테스트용, 메인에는 메모리가 더 나오는 **단독형**이 맞다.

### 추천 상품

| 역할 | 상품 (이름) | 사양 | 월 요금 | 왜 |
|------|-------------|------|---------|-----|
| 일반 고객 메인 | **gna_4.16_n** (단독) | 4코어 / 16GB | 약 6.2만 | 다수 사이트를 올리려면 메모리가 중요 |
| 위와 동일 2호 | **gna_4.16_n** | 동일 | 약 6.2만 | 한 대에 129개를 몰지 않기 위함 |
| 트래픽 큰 고객 | **gna_2.8_n** (단독) | 2코어 / 8GB | 약 3.3만 | 소수 사이트가 전체를 잡아먹지 않게 분리 |
| (참고) 공유형 최대 | vgna_8_n | 8코어 / 8GB | 약 4.6만 | 파일럿·소수만. 메인엔 메모리 부족하기 쉬움 |
| 데이터 디스크 | SATA 블록스토리지 | 500GB~1TB대 | 용량에 비례 | OS 디스크와 분리해 사이트 데이터 보관 |

### 월 비용이 대략 어떻게 나오나 (전량에 가깝게 옮긴다고 가정)

| 구분 | 대략 |
|------|------|
| 서버 3대 | 약 **16만** |
| 데이터 디스크 | 약 **8만** |
| 트래픽(월 ~5TB대, 기본 제공 초과분) | 약 **20만** 전후 |
| **합계 감** | **월 약 40만 원대** (부가세 별도) |

관리 화면(제어판)은 무료(aaPanel)로 시작할 수 있고, 유료 패널(Plesk)을 쓰면 라이선스가 추가된다.

### 꼭 알아둘 점

1. **트래픽 요금이 생각보다 크다.** 서버비만 보고 싸다고 느끼기 쉬운데, 방문·다운로드가 많은 사이트는 초과분이 서버비와 맞먹을 수 있다.  
2. **처음부터 전량 이전할 필요는 없다.**  
   - 1단계: 서버 1대(~8만+소수 트래픽)로 검증  
   - 2단계: 가벼운 계정부터 이전  
   - 3단계: 트래픽 큰 계정·전량  
3. 트래픽 큰 사이트를 **당분간 카페24에 남겨 두면** 자체 쪽 월 비용을 크게 줄일 수 있다.  
4. 위 금액은 **감(感)** 이다. 실제는 이전 범위·트래픽·디스크 종류에 따라 달라진다.
