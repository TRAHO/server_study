# 호스팅 운영 방식 브리핑

**대상:** 카페24 리셀러(현행) / 스마일서브 iwinv 자체 호스팅(검토 중인 운영 방식)  
**성격:** 두 방식의 구조·특성·차이를 설명하는 브리핑 자료  
**상세 운영·대응 방법:** 하단 [주제별 문서](#주제별-문서) 참고

---

## 1. 한눈에 보기

두 방식 모두 고객에게 도메인·계정·용량 단위의 “호스팅 방”을 제공한다.  
갈리는 지점은 **서버를 누가 소유하고, 장애·보안·백업을 누가 책임지느냐**이다.

| | 카페24 리셀러 | iwinv 자체 호스팅 |
|--|---------------|-------------------|
| 서버 | 카페24 | 에이전시(가상 서버) |
| 인프라 복구 | 플랫폼 | 내부 |
| 방 나누기 | 카페24 플랫폼 | 제어판(Plesk/aaPanel 등) |
| 고정비 | 낮음(고객 없으면 서버비 거의 없음) | 서버·스토리지 월정액 |
| 구성 자유도 | 상품 범위 안 | 높음(OS·스택 직접) |
| 운영 부담 | 상대적으로 낮음 | 상대적으로 높음 |

---

## 2. 각 방식이 어떻게 돌아가는지

### 카페24 리셀러

에이전시가 계정·도메인·고객 응대·과금을 맡고, 서버·네트워크·스토리지 운영은 카페24 플랫폼이 담당한다.

```
에이전시 ──(계정 생성)──▶ 카페24 서버 팜(여러 노드)
                              ├─ 노드A (고객들)
                              ├─ 노드B (고객들)
                              └─ ...
```

### iwinv 자체 호스팅

에이전시가 가상 서버를 구매하고, 제어판으로 고객 방을 만들며, OS·웹스택·백업·보안까지 직접 운영한다.

```
에이전시 ──(제어판)──▶ iwinv 가상서버
                         ├─ 고객A
                         ├─ 고객B
                         └─ ...
```

서버를 여러 대 두면 분산 **형태**는 카페24와 비슷해 보일 수 있다.  
다만 계정 자동 배정·통합 관리 플랫폼까지는 별도로 갖춰야 하며, 서버만 늘린다고 동일해지지는 않는다.

---

## 3. 고객 “방”은 어떻게 나뉘는가

기술적으로 둘 다 **공유 호스팅**에 가깝다. (방 = 기본으로 별도 VM이 아님)

| | 가능 | 기본으로는 아님 |
|--|------|----------------|
| 도메인·디스크·DB·SSL·트래픽 상한 | 방마다 분리·할당 | |
| 서버·공인 IP·전체 회선 | | 여러 방이 공유 |
| 노드(서버) 장애 시 | | 그 노드(VM)에 있는 고객이 **같이** 영향 |

카페24와 자체의 차이는 “동시 영향이 있느냐”보다 **복구·격리·루트 권한을 누가 갖느냐**에 있다.

## 4. 장단점 요약

### 카페24 리셀러

| 장점 | 단점 |
|------|------|
| 인프라 운영 부담이 적음 | 상품·모듈·스펙 제약 |
| 인프라 장애 복구는 플랫폼이 수행 | 원가·정책이 플랫폼에 종속 |
| 상품 단위 확장이 단순 | 특수·커스텀 환경에 불리할 수 있음 |
| 현행 유지 시 전환 리스크 없음 | 인프라 가시성·통제권 제한 |

### iwinv 자체 호스팅

| 장점 | 단점 |
|------|------|
| 스택·보안·용량 정책을 직접 설계 | 장애·보안·백업의 최종 책임이 내부 |
| 장기·규모에서 원가 통제 여지 | 고객이 없어도 서버 고정비 |
| 네임서버·제어판 등 브랜드 자체화 용이 | 리눅스·패널 운영 인력·지식 필요 |
| 레거시·특수 환경 맞춤에 유리 | 단일 VM 집중 시 영향 범위·운영 복잡도 증가 |

## 6. 자체 호스팅에서 달라지는 운영 성격

자체로 가면 “호스팅 공장”을 직접 돌리게 된다. 아래는 **의사결정 체크가 아니라**, 운영 방식이 바뀌며 생기는 특성이다.

| 영역 | 무엇이 달라지는가 |
|------|-------------------|
| 장애 | 인프라 복구 주체가 내부. 다수 동시 영향은 카페24 노드 장애와 같은 유형 |
| 보안 | 루트 SSH·자체 패널·OS까지 내부 관리. CMS 해킹 자체는 양쪽 모두 가능 |
| 백업 | 서버 밖 백업·복구 절차를 직접 운영 |
| 이전 | OS·PHP 버전 차이로 사이트별 검증 부담 |
| 규모 | 서버 추가·고객 배정·이중 창구(리셀러 병행 시)를 내부에서 설계 |

영역별 대응·완화 방법은 아래 주제 문서로 분리했다.
