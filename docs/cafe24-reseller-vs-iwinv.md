# 카페24 리셀러 vs iwinv 자체 호스팅

지금은 **카페24 리셀러**로 운영 중이고, 로드맵은 **iwinv 가상 서버 + 제어판**으로 자체 호스팅을 만드는 경로다.  
둘 다 “고객에게 호스팅을 제공”하지만, **서버를 누가 갖고 책임지느냐**가 핵심 차이다.

---

## 한눈에 비교

| | **카페24 리셀러 (현재)** | **iwinv + 제어판 (로드맵)** |
|--|---------------------------|------------------------------|
| 서버 주인 | 카페24 | **우리** |
| 장애·보안·백업 1차 | 카페24 쪽이 큼 | **우리가 큼** |
| 제어판·입주 | 카페24 리셀러 시스템 | Plesk / aaPanel |
| 스펙·구성 | 상품 패키지 안 | OS·Apache·PHP·용량을 **직접** |
| 초기 난이도 | 낮음 | 높음 (서버·방화벽·백업 직접) |
| 마진 구조 | 카페24 도매가 − 판매가 | 서버비 등 **원가 − 판매가** |
| 고객 방 분리 | 카페24 인프라에서 계정 분리 | 한 서버 안을 제어판으로 분리 |

---

## 항목별 차이

### 1. 책임

| | 리셀러 | 자체 |
|--|--------|------|
| 서버 다운·디스크·네트워크 | 대체로 카페24 | **우리가 대응** |
| 해킹·백업 실패·용량 부족 | 플랫폼 + 우리 응대 | **우리 중심** |
| 고객 응대·도메인 연결·계정 | 우리 | 우리 |

### 2. 자유도

- **리셀러:** PHP 버전·모듈·크론·특수 설정이 상품 제한에 걸릴 수 있음.
- **자체:** 현재 스택(Apache / MariaDB / PHP)에 맞게 **원하는 대로** 구성 가능. 대신 맞춤·유지는 우리 몫.

현재 운영 스택 참고 → [current-stack.md](./current-stack.md)

### 3. 비용

- **리셀러:** 고객 수·상품만큼 카페24에 납부. 고객 없으면 서버 고정비는 거의 없음.
- **자체:** 고객 0명이어도 **가상 서버 월정액**이 나감. 고객이 많아질수록 원가 대비 마진 여지는 커질 수 있음.

비용 항목·이유 → [costs.md](./costs.md)

### 4. “방마다 독립”

- **리셀러:** 카페24 위에서 계정별로 나뉨. 고객 체감은 독립 호스팅에 가까움.
- **자체:** 한 가상 서버를 제어판으로 나눔.
  - 되는 것: 도메인·디스크·DB·SSL·트래픽 상한(할당)
  - 안 되는 것: 서버·공인 IP·전체 회선의 완전 독립 (기본 구성 기준)

### 5. 확장

- **리셀러:** 상품 추가·업그레이드가 단순.
- **자체:** 스펙업·서버 추가·이전이 **우리 작업**. (~100개·~300개 가이드는 [phase-2-iwinv.md](./phase-2-iwinv.md))

### 6. 브랜드

- 둘 다 고객 앞에서 에이전시 브랜드로 보일 수 있음.
- 자체는 네임서버·제어판 주소까지 **완전 우리 간판**으로 가져가기 쉬움.

## 언제 뭐가 맞는지

| 상황 | 선택 |
|------|------|
| 운영 부담 최소·안정 우선 | **카페24 리셀러** |
| 원가 통제·특수 서버 설정·장기 규모·마진 | **iwinv 자체** |
| 현실적인 병행 | 일반 고객은 리셀러, 특수·중요 고객만 자체 등 |

자체 호스팅은 “호스팅 공장”을 직접 돌리는 것이라, 리셀러보다 **기술·장애 대응 비용**이 올라간다.
