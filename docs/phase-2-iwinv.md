# Phase 2. iwinv 인프라 구축

## 목표

스마일서브 클라우드(iwinv)에 서버·디스크·방화벽을 준비한다.

## 2-1. 인스턴스 생성

1. [iwinv 콘솔](https://www.iwinv.kr/) 가입·로그인
2. 상품(라인) 선택 → 서버 생성
   - OS: Ubuntu Server 22.04 LTS 또는 24.04 LTS
   - 사양: 아래 규모별 가이드 참고

### 상품이 많을 때 — 뭘 고르나

콘솔에 보통 아래 3가지가 나온다. **에이전시 호스팅 시작은 General Purpose만 고르면 된다.**

| 상품 | 특징 | 언제 |
|------|------|------|
| **General Purpose** (줄여서 **GP**) | AMD + NVMe, 합리적 가격, 범용 | **기본 선택** (웹·제어판) |
| High Performance | AMD EPYC + NVMe, 안정·성능 중시 | CPU를 계속 태우는 쇼핑몰·대형 트래픽 |
| Storage Optimized | Intel Xeon + SSD, 스토리지 중심 | 디스크 용량·I/O가 핵심일 때 (우리는 데이터는 블록스토리지로 분리하므로 초기엔 불필요) |

**다음 클릭 순서:** General Purpose → Ubuntu 22.04/24.04 → 스펙 선택

> 기존 운영 서버는 CentOS 7이다. **신규에는 CentOS 7을 쓰지 않는다** (EOL).  
> 현재 스택·호환 목표 → [current-stack.md](./current-stack.md)

### iwinv 하드웨어 SKU 예시 (GP 화면)

| 선택 | 상품명 | 스펙 | 비고 |
|------|--------|------|------|
| **추천 (초기)** | **vgna_8_n** | 공유형 8Core / 8GB | 제어판+Apache+MariaDB+PHP 여유 |
| 최소 | vgna_4_n | 공유형 4Core / 4GB | 테스트용, 금방 부족 |
| 비추천 | vgna_1_n ~ vgna_2_n | 1~2GB | 메모리 부족 |
| 이후 | gna_* (단독형) | — | 트래픽·안정성 필요 시 |

ZONE은 **KR1-ZONE**이면 충분하다.

### 규모별 스펙·구성 가이드

사이트 수 ≠ 트래픽이다. 한산한 기업 홈페이지 위주면 사이트 수보다 **메모리·분산**이 먼저 부족해진다.

| 고객 수 (대략) | 권장 |
|----------------|------|
| **~10개** (초기) | GP **vgna_8_n (8Core/8GB)** 또는 동급 + 데이터 디스크 50~100GB |
| **~30~50개** | GP **4Core / 16GB** + 데이터 디스크 200GB+ |
| **~100개** | GP **8Core / 32GB** 또는 서버 **2대 분리**. 메모리가 먼저 부족해짐. High Performance는 “특정 고객이 CPU를 태울 때”만 |
| **~300개** | **한 대에 몰지 말 것.** 웹/제어판 **2~3대**(대당 ~100개)로 분산. 트래픽 큰 고객만 HP·단독 분리. 디스크 대당 500GB~1TB+, 외부 백업 필수 |

**300개일 때 운영 포인트**

1. 서버 A / B / C에 고객을 나눠 입주
2. 네임서버·백업·모니터링은 공통 관리
3. 신규 고객은 여유 있는 서버에 배정
4. 트래픽 큰 고객만 고스펙/단독으로 분리

> 스펙·대수는 나중에 콘솔에서 늘릴 수 있다. 지금은 GP 1대로 시작하고, 100개 전후부터 2대째를 열어두면 된다.

## 2-2. 블록 스토리지 추가·마운트

OS 디스크와 분리해 웹/DB용 SSD를 붙인다. (예: 50~100GB)

SSH 접속 후 예시 (디스크 장치명은 콘솔/환경에 맞게 확인):

```bash
# 디스크 확인
lsblk

# 파티션·파일시스템 (최초 1회, 장치명 확인 후)
sudo mkfs.ext4 /dev/vdb

# 마운트 포인트
sudo mkdir -p /data
sudo mount /dev/vdb /data

# 재부팅 후에도 유지 (UUID 확인 후 fstab)
sudo blkid /dev/vdb
# /etc/fstab 에 UUID=.... /data ext4 defaults 0 2 추가
```

> 용량 부족 시 서버 전원 없이 디스크만 확장하는 것이 목적.
